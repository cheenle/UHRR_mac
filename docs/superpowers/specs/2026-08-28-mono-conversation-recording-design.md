# MRRC 单声道通联录音设计

## 目标

将现有 RX 左声道、TX 右声道且时间未对齐的录音，改为按真实时间顺序播放的单声道通联录音。

成功标准：

- 录音按“接收 → 发射 → 接收”的实际顺序播放。
- PTT 开启期间以 TX 为准，不混入 RX 回采、串音或底噪。
- RX 录制用户实际听到的 WDSP 处理后音频。
- TX 录制实际送往电台播放、完成服务端增益与限幅后的音频。
- 多次 PTT 之间的时间间隔得到保留，不把所有 TX 压缩到文件开头。
- 输出继续兼容现有录音列表与播放器，采用 16 kHz、16-bit、单声道 MP3。

## 已确认根因

当前实现分别顺序累积 RX 和 TX：RX 从开始录音后持续写入，TX 仅在收到发射音频帧时写入。停止录音时，两组样本从数组起点直接组成左右声道，较短声道只在尾部补零。由于数据不含会话时间位置，后发生的 TX 会被移动到文件开头并与早期 RX 重叠。

现有录音分析与此一致：部分约 60–70 秒文件的 TX 右声道只出现在文件开头数秒，其余部分全为静音；另有文件右声道完全静音。

## 架构

### RecordingSession

在 `audio_interface.py` 中集中管理单个进程级录音会话：

- 使用 `time.monotonic_ns()` 建立会话时间基准，避免系统时间调整影响位置。
- 接收带来源、采样率、时间戳和 PCM 数据的音频块。
- 每个来源拥有独立的有状态降采样器，统一转换为 16 kHz Int16。
- 保存带目标样本偏移的事件，而不是两个从零开始的独立声道数组。
- 停止时构建单声道时间轴；无数据区域保持静音。
- 同一位置发生重叠时 TX 覆盖 RX。

保留现有模块级 `start_recording()`、`stop_recording()` 和 `get_recording_status()` 接口，避免前端和 WebSocket 协议变化。

## 数据流

### RX

1. 音频设备以 48 kHz 捕获。
2. 完成现有基础电平处理和 WDSP 处理。
3. 取得即将用于 RX 编码/播放的 PCM。
4. 仅在录音开启且 PTT 未开启时，以当前单调时钟写入录音会话。
5. 使用 RX 专属有状态抗混叠降采样器转换为 16 kHz。

若 WDSP 尚未产生完整输出块，本帧不写入；其自然形成的微小处理延迟由时间轴保留。

### TX

1. 浏览器 TX 帧经 Opus 解码或 PCM 解析。
2. 服务端完成与实际播放一致的平滑增益及软限幅。
3. 将实际排入播放队列的 PCM 暴露给录音路径。
4. 仅在录音开启且 PTT 发射流程有效时，以当前单调时钟写入录音会话。
5. 使用 TX 专属有状态抗混叠降采样器转换为 16 kHz。

### PTT 优先级

- 发射期间不写 RX，防止电台回采或声卡串音混入录音。
- 时间轴合成仍执行 TX 覆盖 RX，处理线程边界附近可能存在的竞态。
- PTT 释放后恢复 RX，时间间隔按真实时长保留。

## 编码与质量

- 中间格式：16 kHz、16-bit、单声道 PCM。
- 输出格式：MP3，继续使用 `libmp3lame` 高质量 VBR，保持现有下载与播放兼容。
- 不使用当前 TX 的 `samples[::ratio]` 简单抽取；RX、TX 都使用有状态低通降采样，避免混叠和帧边界爆音。
- RX 来源为 WDSP 后音频，TX 来源为服务端实际播放 PCM，因此录音更接近双方真实听感。

## 并发与限制

- 录音状态和事件列表由同一把锁保护。
- 音频处理在锁外完成，仅在提交事件时短暂持锁，避免阻塞音频线程和 Tornado IOLoop。
- 停止录音时先原子关闭会话并取出事件快照，再在锁外合成和调用 ffmpeg。
- 保留最长录音限制；按会话实际时长和样本数量判断，而不是仅计算 RX 块数量。
- 重复开始录音不得静默清空现有会话；应返回失败或保持当前会话。
- 未开始时停止录音应返回明确失败，不生成空文件。

## 错误处理

- ffmpeg 不存在、超时或编码失败时记录完整错误并返回失败。
- 编码失败不广播 `recordingSaved`。
- 前端以服务端确认作为最终状态；请求发送后可显示“正在启动/停止”，收到失败时恢复正确按钮状态。
- 连接断开不伪造“保存成功”。

## 测试

添加不依赖真实声卡和电台的测试：

1. RX、TX、RX 三段按时间戳落在正确位置。
2. 多次 PTT 不会把 TX 片段压缩到录音开头。
3. TX 与 RX 重叠时只保留 TX。
4. 时间间隔输出静音。
5. 48 kHz 输入降到 16 kHz后，时长和音调保持正确。
6. 重复开始、空停止和编码失败返回正确状态。
7. 生成文件经探测为 16 kHz 单声道。

## 范围

本次只修改录音采集、时间轴合成及必要的状态反馈，不重构实时 RX/TX 播放协议，不改变 PTT 的既有安全清队列顺序，也不修改录音列表页面协议。
