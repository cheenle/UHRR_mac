## 2. 阶段历程

### Phase 0（2024-10 → 2026-02，父项目）：从零到可用

V1.0 → V4.3 在父项目完成：核心架构（Tornado + WebSocket + PyAudio + Hamlib/rigctld + Opus）、桌面/移动双界面、基础录音。FDE 指导书将这阶段定义为"驻场找真问题"——用户（作者自己，呼号 BG1SB）就是第一个重度用户，日常通联即测试场。

### Phase 1（2026-03，48 commits）：Mac 移植爆发期

本仓诞生（首个提交 `ba66892` 即 V4.6.0 TX AudioWorklet 重构）。一个月的密集战役：

- **ATR-1000 天调接入 saga**（V4.5.11→V4.5.18）：SYNC 节流、设备压力控制、防断连重连、智能学习、快速调谐、API 服务器重构——第一个"设备很脆弱、软件必须围着它跳舞"的教训。
- **首次线程化战役**：`ba66892`（TX AudioWorklet 重构解决主线程阻塞）→ `1a072b3`（ATR 广播线程安全，用 `IOLoop.add_callback`）→ **`d4a40c2` 回滚 V4.6.0 AudioWorklet/Worker 架构**。回滚是重要时刻：新架构引入的问题比解决的多，果断退回。
- **品质与安全**：V4.6.0 高品质语音版 + ATU 自动天调；V4.7.0 WDSP 优化；V4.8.0 音频系统重构 + 录制；V4.9.x 多实例部署、远程隧道、S 表校准、双语界面（03-21 中文 UI + 完整英文文档翻译）。

### Phase 2（2026-04，4 commits）：静默期

只有一个移动端正修复 + WDSP NF，月底 V5.0.0 移动端 UI 全面现代化。**低提交量 ≠ 停滞**：这是"用出来的"阶段——产品在真实通联中跑，问题在积累。

### Phase 3（2026-05 → 06，67 commits）：音质军备竞赛 + 方法落成

- **TX 音质链**：V5.1 RagChew 模式（Web Audio 均衡/压缩链）；V5.2 WDSP 配置缓存 + RX 播放引擎重写；V5.3 RX 卡顿修复（AudioWorklet 缓冲策略**回滚**——又一次"新不如旧"的决断）。
- **降噪第一战**（05-31）：`ac651e6` WDSP NR2 级别重写，Gaussian 替代 Gamma 消除"数码音"——降噪问题的第一次指标化尝试。
- **ATR 学习 saga**（06-06→06-09，V5.6.0→V5.6.4）：稳定窗口学习缓冲器防假 SWR 污染 → 继电器状态保留 → 调谐完成检测加速 → 学习去重。四个版本修同一个"学习"功能，典型的状态机调试。
- **方法落成**（05-10、06-06、06-11）：FDE 实践指导书成文 → Aladdin V2 方法论 → SDD 浮出水面为 vibe coding 核心。**方法论不是写在前面的，是从项目里长出来的。**
- 副产物：网站统计 dashboard（日志解析 + GeoIP + SQLite 聚合）、网站重设计、EFHW 天线知识专区。

### Phase 4（2026-08，55 commits）：V5.7/V5.8 大整修——最狠的一个月

### Phase 5（2026-09，31 commits 至今）：跨平台 + 降噪深水区 + RC-001

## 3. 问题图谱：反复出现的问题类与最终解法

### 3.1 线程与事件循环阻塞——贯穿全程的第一主题（5 次战役）

| 时间 | 战役 | 修的什么 |
|------|------|----------|
| 2026-03-06 | `ba66892`/`1a072b3` | TX 主线程阻塞、ATR 广播线程安全 |
| 2026-03-07 | `d4a40c2` | 新架构回滚（过度工程化） |
| 2026-08-09 | V5.8.1/V5.8.2 | rigctld I/O 进执行器（F3）、MAIN_IOLOOP 固定 |
| 2026-08-28 | F2（代码注释） | `stream.write()` 挪出 IOLoop |
| 2026-09-14 | RC-001 F4/F4b | 构造函数 `p.open()`——最后一个漏网的阻塞点 |

**教训沉淀**：前四次都是"哪里卡修哪里"，RC-001 才把问题总结为纪律——**IOLoop 线程零阻塞**，并配看门狗把纪律变成可观测的约定。从"修点"到"修面"用了 6 个月。

### 3.2 音频质量——耳朵与指标的双轨演化

RNNoise → WDSP → EMNR Gaussian 重写（数码音）→ 48k/16k 采样率之争（水音）→ NR2 SSB 语音保护（吃语音，C 补丁 + 指标验收）。演化路线是**从纯听感走向可量化**：voiceΔ（吃语音量）、noiseΔ（降噪强度）、LSD（变形量）、jitter（音乐噪声）四个指标把"听着不对"翻译成测试断言。

### 3.3 设备脆弱性——围着不可靠外设设计

ATR-1000 的 SYNC 节流、防断连、学习污染、SWR 守卫，加上今天的蓝牙 DAC——**所有不可靠外设的应对模式是同一套**：代理隔离 + 缓存应答 + 压力控制 + 异常观测。协议边界永远假设对端会卡。

### 3.4 安全——PTT 是唯一的物理安全面

PTT Safety Monitor（释放失败后台重试 + TOT 硬上限）、5 秒无帧收 PTT、方向感知状态机（R3，释放方向绝不乐观）、SWR>2 自动调谐守卫、RC-001 丢弃路径强制释放。**发射状态机的每一次修复都是"软件状态可能骗你，电台不会"**。判据从软件断言下沉到物理量（ATR 功率计）。

### 3.5 环境边界——代码外的世界

RC-001 是第一次把根因钉在系统外（杂牌蓝牙固件不应答 Jitter Buffer 配置 → CoreAudio 全局阻塞）。同类先例其实早有（音频设备枚举、USB 串口、证书链），但这次第一次把探针装进系统层（unified log / bluetoothd / SwitchAudioSource）。

```text
手工试错（父项目早期）
  → 日志 + 功率计观察（V4.5 ATR saga）
  → spec/plan + 手动验收（V5.x）
  → 红绿测试 + 四指标 + A/B 试听（V6.0.1）
  → 运行时遥测：看门狗 / ⏱️打点 / .prev 死亡现场（V6.0.2）
```

验证深度每过一重大版本上一个台阶；方向始终是**离物理真相更近、离猜测更远**。

## 7. 进一步思考提炼（元教训）

1. **修点不修面，问题会换着面孔回来**。线程阻塞类问题修了 5 次才变成纪律。对反复出现的同类问题，正确动作是"枚举所有可能点 + 立规矩 + 装探针"，而不是等下一次事故。
2. **异步化移动 bug，不消灭 bug**。每把一个阻塞点挪出关键线程，必须先回答"阻塞窗口内到达的数据和事件去哪了"。RC-001 二期（帧静默丢弃）就是一期修复的直接副作用。
3. **环境问题不等于代码问题**。在改代码之前，把观测做到系统边界（OS 日志、硬件读数）。今天的 ATR 功率计和 bluetoothd 日志比任何 Python 日志都更快定位真相。
4. **物理量是终极断言**。软件每一层都可以"看起来正常"，电台发射功率不会撒谎。怀疑软件链路时，先找一个硬件读数对照。
5. **1 人 + AI 的形态被验证了，但纪律不能省**。FDE cycle、spec-first、红绿验收、postmortem——AI 加速的是执行，不是判断；没有纪律的 AI 加速只是把债还得更快。
6. **减法是架构能力**。V5.7 删 FT8/CW、两次回滚、菜单瘦身——每次"砍"都对应可靠性或可用性的上升。敢于删功能的项目才有长期演进空间。
7. **文档的复利**。CHANGELOG 35 版 + 案例库 + code-first docs，让今天这份复盘完全由数据写成——没有回忆，没有美化，只有 git 里的证据。
