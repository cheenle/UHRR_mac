出问题先拿诊断包

"日志里写了什么"这句话，三次点击就能回答，不用翻文件夹。

🐞 什么时候用

屏幕上解释不了的事：声音一顿一顿、面板不再刷新、电台连不上、点了升级毫无反应、某个页面的按钮集体失灵。

没有证据的上报只能靠猜。诊断包存在的意义，是把第一个回答变成结论，而不是又一句反问。

🧭 三步

#你做什么为什么重要
1打开 🐞 遇到问题，写清现象——什么表现、从什么时候开始、电台型号和频率"换到 Windows 这台机器后，接收每隔约 1 秒卡一下"能查；"不能用"不能查
2点【生成诊断包】收集日志、脱敏配置、环境快照，并跑一遍自动体检
3点【上传给维护者】，或【只保存到本地】你点了才会上传

这一页要求你先登录本机 MRRC 界面；没有会话时它返回 401/403。

📦 包里有什么

  • 日志尾部——各角色的日志末尾，不是整部历史
  • 脱敏后的配置——按白名单取值，敏感项替换，被略去的键会计数
  • 环境快照——平台、版本、设备
  • 自动体检结论——日志新鲜度、音频健康、热修与 WDSP 状态、启动次数与时间跨度（区分重启和崩溃）、音频设备判定

绝不包含什么

用户数据库、证书私钥、会话密钥、任何口令与令牌。不论脱敏与否，都不打进去。

📴 上传不出去怎么办

防火墙、到接收端没有路由、或者这台机器根本不上外网：点【只保存到本地】，再用你现成的渠道把文件递过来。

诊断包就是一个普通文件，能上传只是替你省一步。

🔎 之后会发生什么

  1. 新上报会被抓取、摘要，并按本项目的分诊纪律过一遍：结论保守、没有证据不下结论、"环境问题"不算缺陷。
  2. 每一条结论都会变成一张卡：编号 / 症状 / 诊断（附证据）/ 结论 / 你要做的。
  3. 卡片发到公开答复页，可以按编号或关键词搜到。

证据不足时结论就是 need_more_info，绝不给猜测——这也正是体检摘要必须进包的原因。

📚 细节在哪

  • 诊断包与自动分诊
  • 产品支持生命周期——发版 → 升级 → 诊断 → 分诊 → 答复
  • 公开答复页——先看这里，你的症状可能已经有卡
